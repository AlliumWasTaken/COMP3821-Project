Overview

Introduced by David Karger in 1993, Karger’s Min Cut Algorithm solves the global minimum cut problem on undirected multigraphs using randomized edge contractions [2].

While deterministic algorithms execute a completely determined sequence of states yielding the exact same output for an input, randomized algorithms incorporate random choices governed by a probability distribution. This prevents adversaries from constructing worst-case inputs and often results in substantially simpler algorithms.

Randomized algorithms are broadly categorized into two groups [3]:

Category Las Vegas Algorithms Monte Carlo Algorithms
Correctness Guaranteed Uncertain (Bounded failure rate)
Running Time Uncertain (Random variable) Guaranteed (Deterministic bound)
Example Randomized QuickSort Karger's Min Cut, Miller-Rabin

Karger’s algorithm is a Monte Carlo algorithm, its execution time is fixed and strictly bounded, but each single trial has a small probability of returning a sub-optimal cut.

Intuition

Consider a graph whose minimum cut has size k. By definition, exactly k edges cross this cut, while the total number of edges in the graph is typically much larger (at least nk/2).

If an edge is selected uniformly at random, the odds of picking one of the k critical cut edges are relatively low (at most 2/n in the first step). The algorithm is statistically more likely to contract an edge located safely inside one of the partitions. Repeating contractions until only two super-nodes remain yields a non-trivial probability that the true minimum cut was never contracted.

Pseudocode

Given an undirected multigraph G = (V, E) with |V| = n:

  1. While |V| > 2:
    1. Choose an edge e = {u, v} ∈ E uniformly at random.
    2. Contract e to form G / e (merge endpoints, remove self-loops, keep parallel edges).
  2. Return the cut defined by the two remaining composite vertices.

Worked Example

Proof of Correctness

Following Karger [2] and Yu [9], we analyze the probability that a specific global minimum cut (X, X̄) of size k survives all n − 2 contractions on a connected multigraph G = (V, E) (with parallel edges kept and self-loops removed).

Cut Correspondence

Let G' be obtained from G by a sequence of edge contractions. There is a one-to-one correspondence between cuts (Y, Ȳ) of G' and cuts (X, X̄) of G that survived every contraction (meaning no contracted edge had one endpoint in X and one in X̄), and both cuts have the exact same size. In particular, every cut in G' has size at least k.

Edge Lower Bound Lemma

Let G be an undirected multigraph with no self-loops and minimum cut value k. Then |E(G)| ≥ nk / 2.

Proof: For every vertex v ∈ V, the singleton partition ({v}, V \ {v}) is a valid cut of size exactly deg(v). Since k is the minimum cut value, deg(v) ≥ k for all v ∈ V. By the Handshaking Lemma [1], |E| = (∑v ∈ V deg(v)) / 2 ≥ nk / 2.

Single Step Survival Corollary

Let (X, X̄) be any minimum cut of G. The probability that (X, X̄) survives a single random edge contraction is at least 1 − 2/n.

Proof: By the Edge Lower Bound Lemma, there are at least nk / 2 edges in G, and exactly k of them cross (X, X̄). Selecting an edge uniformly at random hits (X, X̄) with probability k / |E| ≤ k / (nk / 2) = 2/n. Thus, (X, X̄) survives with probability at least 1 − 2/n.

Theorem [Karger 1993]

For any undirected multigraph G and any global minimum cut (X, X̄), a single run of Karger's algorithm outputs (X, X̄) with probability at least 2 / (n(n − 1)).

Proof: By Cut Correspondence, the algorithm outputs (X, X̄) if and only if (X, X̄) survives all n − 2 contractions. Conditioned on surviving the first i − 1 contractions, the current multigraph has n − (i − 1) = n − i + 1 super-vertices, no self-loops, and (X, X̄) remains a minimum cut of value k. Applying the Single Step Survival Corollary to the i-th contraction gives a conditional survival probability of at least 1 − 2 / (n − i + 1). By the chain rule of conditional probability, the overall probability that (X, X̄) survives every contraction is at least:

∏i=1..n-2 (1 − 2 / (n − i + 1)) = ∏i=1..n-2 ((n − i − 1) / (n − i + 1)) = ((n − 2)/n) × ((n − 3)/(n − 1)) × ((n − 4)/(n − 2)) × … × (2/4) × (1/3) = 2 / (n(n − 1)).

Corollary (Number of Minimum Cuts): Because a single run outputs only one cut, the events of outputting distinct minimum cuts are disjoint. Since each has probability at least 2 / (n(n − 1)) = 1 / C(n, 2) and the sum of probabilities cannot exceed 1, any graph has at most C(n, 2) = n(n − 1) / 2 global minimum cuts [2, 5].

Probability of Success

From the above theorem, a single execution finds a specific minimum cut with probability at least:

P(Single run succeeds) ≥ 1 / C(n, 2) = 2 / (n(n − 1)).

While Ω(1/n2) is small, Karger's algorithm is a Monte Carlo algorithm whose success probability can be improved by running multiple trials and returning the smallest cut found.

Including Reruns: Given that for all x > 0, (1 − 1/x)x ≤ 1/e, and that the algorithm is incorrect only if every run fails to find the minimum cut:

P(Karger reruns are incorrect) = P(Karger is incorrect for all C · C(n, 2) ln n independent runs)

= [ P(Single run is incorrect) ]C · C(n, 2) ln n

≤ [ 1 − 1 / C(n, 2) ]C · C(n, 2) ln n

= [ (1 − 1 / C(n, 2))C(n, 2) ]C ln n

≤ (1 / e)C ln n = e−C ln n = 1 / nC.

Thus, running Karger's algorithm c · (1/P) ln n times and selecting the best result guarantees an amplified success rate of at least 1 − 1/nc [10].

Time and Space Complexity

The complexity of Karger's algorithm breaks down into multiple parts:

  • Single Run Time O(n2): The algorithm performs exactly n − 2 edge contractions. Merging two vertices {u, v} requires scanning at most O(n) incident edges. Thus taking (n − 2) × O(n) = O(n2) per run.
  • Multiple Runs Time O(n4 log n): To achieve a failure probability of at most 1/n, we perform n2 ln n repetitions. The total running time is thus:
    O(n2) × O(n2 ln n) = O(n4 log n).
  • Space Complexity O(n + m): The algorithm only needs to maintain the current graph and vertex mappings, requiring only linear space proportional to the original vertices and edges.

The O(n4 log n) runtime can be improved significantly. The recursive Karger-Stein Algorithm branches on partially contracted graphs to achieve O(n2 log3 n), and Karger's tree-packing approach [11] gets the near linear O(m log3 n) time.
