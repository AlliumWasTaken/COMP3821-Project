Overview

The Stoer-Wagner algorithm, created by Mechthild Stoer and Frank Wagner in 1994, solves the global minimum cut problem deterministically and without computing maximum flow. It takes an undirected graph G = (V, E) with n = |V| vertices and a nonnegative edge weight w(e) on every edge. An undirected graph is the case where every edge weight is 1, and a multigraph can be collapsed into this form by summing parallel edges.

Intuition

The algorithm runs |V| − 1 short phases, each of which produces one candidate cut, and then merges two vertices to shrink the graph. The lightest candidate over all phases is the minimum cut.

The foundational logic for this approach is that for any two vertices s and t, the true global minimum cut must either separate s and t, or it must place them on the same side. By finding the minimum cut separating a specific s and t (the cut of the phase), we evaluate the first scenario. If that cut is not the global minimum, s and t must belong to the same side of the global minimum cut, meaning we can safely merge them into a single vertex without destroying the true minimum cut.

Minimum Cut Phase

For a set of vertices X and a vertex v ∉ X, let w(X, v) be the total weight of the edges between X and v. The algorithm runs as follows:

  1. Choose an arbitrary starting vertex and let X be the set containing only that vertex.
  2. While X ≠ V, add the vertex v ∉ X that maximises w(X, v) to the set X. Let t be the last vertex added and s the vertex added just before it.
  3. The cut of the phase is the cut (A, B) with A = {t} and B = V \ {t}, which separates the vertex added last from the rest of the graph. Its weight is w(V \ {t}, t). If it is lower than the current minimum cut, store it as the current minimum cut.
  4. Shrink the graph by merging s and t into a single vertex. Any edges from s and t to a remaining vertex are replaced by one edge weighted by the sum of the two previous weights, and edges joining s and t are removed.
  5. While |V| > 1, repeat steps 1 to 4 on the shrunken graph. Each repetition is one phase, and there are n − 1 of them.
  6. Return the stored minimum cut, which is the lightest of the n − 1 cuts of the phase. Each merged vertex is expanded back to the original vertices it represents, so the cut is reported as a partition of V.

Pseudocode

MinimumCutPhase(G, a):
      A <- {a}
      while A != V:
        add to A the most tightly connected vertex
      return s, t, and the cut weight as the "cut of the phase"

    MinimumCut(G):
      minimum cut = nil
      while |V| > 1:
        choose any a from V
        cut of the phase = MinimumCutPhase(G, a)
        if the "cut of the phase" cut is lighter than the current minimum cut:
          minimum cut = cut of the phase
        shrink G by merging the two vertices from the "cut of the phase" (s, t)
      return the minimum cut

Time and Space Complexity

With Fibonacci heaps it runs in O(|V||E| + |V|² log |V|) time, which matched the fastest algorithm known when it was published. The space complexity is O(|V|²) to store the dense adjacency matrix required for rapid weight updates, or O(|V| + |E|) if utilizing adjacency lists, alongside O(|V|) auxiliary space for the priority queue and vertex tracking arrays.
