Problem 1: Tracing Karger's Algorithm by Hand

What you will be able to do after this problem

  1. Trace Karger's algorithm by hand, correctly handling all three contraction cases: an ordinary edge, an edge whose contraction creates parallel edges, and contractions that remove self-loops.
  2. Explain why a run succeeds or fails: it fails exactly when an edge crossing the minimum cut is contracted.
  3. Compute the exact success probability of a single run on a concrete graph and compare it with the general lower bound 2 / (n(n − 1)).
  4. Trace a similar graph on your own.

Notation (the same as the rest of the site). n = |V|, m = |E|, k = size of a minimum cut, G / e = the contraction of edge e. A composite vertex is written as the set of original vertices it contains, e.g. {c, f}. A vertex that has not been merged yet is written as a plain letter, e.g. a. We write X–⁠Y for an edge between (possibly composite) vertices X and Y, and X–⁠Y × 2 for two parallel copies of it.

Reminder of the definitions

  • Contraction G / e for e = {u, v}: replace u and v by one composite vertex, redirect every edge incident to u or v to it, remove self-loops, and keep parallel edges.
  • Karger's algorithm: while more than 2 vertices remain, pick an edge uniformly at random from the current multigraph (each parallel copy counts separately) and contract it. When 2 composite vertices remain, return the cut between them.
  • Karger's algorithm is a Monte Carlo algorithm: its running time is fixed, but it may return a wrong (non-minimum) cut.

1. The problem

Let G = (V, E) be the undirected, unweighted, simple graph with

V = {a, b, c, d, f, g, h}, n = 7,

E = {a–⁠b, a–⁠c, a–⁠d, b–⁠g, b–⁠h, c–⁠f, d–⁠f, g–⁠h}, m = 8.

(We skip the letter e, which denotes an edge, and never use w, which denotes edge weight elsewhere on the site.)

vertexabcdfgh
neighboursb, c, da, g, ha, fa, fc, db, hb, g
degree3322222

Questions.

  1. (Ground truth) Find a minimum cut of G and its value k. Is it unique?
  2. (Trace A) Run Karger's algorithm by hand using the contraction sequence below. After every step, record the chosen edge, the probability of choosing it, the composite vertices, and the full edge multiset.

    c–⁠f, b–⁠h, {b, h}–⁠g, a–⁠d, {a, d}–⁠{c, f}

  3. (Trace B) Do the same for

    g–⁠h, a–⁠b, c–⁠f, {c, f}–⁠d, {a, b}–⁠{g, h}

    Which cut is returned? Is it minimum? If not, at which step did the run go wrong?
  4. (Probability) For trace A, compute at each step the probability that the step does not contract a minimum-cut edge, given that no earlier step did. Then find the exact probability that one run of Karger's algorithm on G returns the minimum cut, and compare it with 2 / (n(n − 1)).

2. Ground truth: the minimum cut

Checkpoint 1: guess first

Every vertex of G has degree at least 2. Does cutting off one vertex of smallest degree, say {c}, give a minimum cut? Can you find a cut whose value is less than 2?

Hint

A cut of value 1 is a single edge whose removal disconnects the graph. Look for an edge that lies on no cycle.

Model answer

Cutting off {c} gives value deg(c) = 2, but that is not the minimum. The edge a–⁠b lies on no cycle: the vertices a, c, f, d form a 4-cycle a–⁠c–⁠f–⁠d–⁠a, and b, g, h form a triangle, and a–⁠b is the only edge between them. Removing it disconnects the graph, so

S = {b, g, h}, V \ S = {a, c, d, f}, cut edges = {a–⁠b}, k = 1.

Brute-force verification. A cut is an unordered pair {S, V \ S} with ∅ ≠ S ≠ V. Fixing a ∉ S lists every cut exactly once, which gives 2n−1 − 1 = 63 cuts. Enumerating all of them (brute_force_min_cut in karger_verify.py) gives:

cut value1234567
number of cuts199191933

So k = 1, and the minimum cut {b, g, h} | {a, c, d, f} is unique. The 9 cuts of value 2 are: {c}, {d}, {f}, {c, f}, {d, f}, {c, d, f} (splitting the 4-cycle side) and {g}, {h}, {g, h} (splitting the triangle side). Remember these, because every failed run will return one of them.

The guess "cut off a vertex of smallest degree" gives 2, not 1. A careless answer is wrong here.

Common misconceptions at this stage

  • "The minimum cut is the smallest degree." The smallest degree is only an upper bound on k. Here it is 2 but k = 1.
  • "There are 2n cuts." S and V \ S are the same cut, and S = ∅ or S = V is not a cut. That leaves 2n−1 − 1.
  • "Min cut means min s–⁠t cut." Karger finds a global minimum cut. No source or sink is given.

3. Worked trace A: a run that succeeds

How to do one step. Before contracting X–⁠Y, check two things:

  1. Multiplicity of X–⁠Y. If there are μ parallel copies, the step's probability is μ/m (any copy gives the same result), and after contracting one copy the other μ − 1 copies become self-loops, which are removed. So m drops by μ.
  2. Common neighbours of X and Y. If both are adjacent to some Z, the edges X–⁠Z and Y–⁠Z both become {X ∪ Y}–⁠Z: parallel edges are created (kept, not merged).

If μ = 1 and there is no common neighbour, the contraction is ordinary: only the one edge disappears and nothing else changes shape.

The minimum-cut edge is a–⁠b. It is marked bold wherever it appears.

Step A1: contract c–⁠f (ordinary)

  • Before: n = 7, m = 8. Edges: a–⁠b, a–⁠c, a–⁠d, b–⁠g, b–⁠h, c–⁠f, d–⁠f, g–⁠h.
  • P(choose c–⁠f) = 1/8.
  • Neighbours of c: a, f. Neighbours of f: c, d. No common neighbour, one copy. This is the ordinary case.
  • New vertex {c, f}. The edge a–⁠c becomes a–⁠{c, f}, and d–⁠f becomes {c, f}–⁠d.
  • After: n = 6, m = 7.

    a–⁠b, a–⁠{c, f}, a–⁠d, b–⁠g, b–⁠h, {c, f}–⁠d, g–⁠h

Step A2: contract b–⁠h (parallel edges created)

  • Before: n = 6, m = 7. P(choose b–⁠h) = 1/7.
  • Neighbours of b: a, g, h. Neighbours of h: b, g. Common neighbour g. So b–⁠g and h–⁠g both become {b, h}–⁠g, which gives two parallel edges. Keep both.
  • The edge a–⁠b becomes a–⁠{b, h}. It is still the one minimum-cut edge, just with a new endpoint name.
  • After: n = 5, m = 6.

    a–⁠{b, h}, a–⁠{c, f}, a–⁠d, {b, h}–⁠g × 2, {c, f}–⁠d

Checkpoint 2: probabilities in the current multigraph

Using the multigraph after step A2, what is the probability that step A3 contracts some copy of {b, h}–⁠g? What is the probability that it contracts the minimum-cut edge?

Hint

Count m for the current multigraph, with each parallel copy counted separately. Do not use the original m = 8.

Model answer

m = 6, and {b, h}–⁠g has 2 copies, so P = 2/6 = 1/3 (each copy alone has probability 1/6). The minimum-cut edge a–⁠{b, h} has one copy, so it is chosen with probability 1/6.

Step A3: contract {b, h}–⁠g (self-loop removed)

  • Before: n = 5, m = 6. P(choose a copy of {b, h}–⁠g) = 2/6 = 1/3.
  • We contract one copy. The other copy now joins {b, g, h} to itself, so it is a self-loop, and it is removed.
  • After: n = 4, m = 4. Two edges disappeared: the contracted copy and the self-loop.

    a–⁠{b, g, h}, a–⁠{c, f}, a–⁠d, {c, f}–⁠d

Checkpoint 3: counting edges

Why did m drop from 6 to 4 in step A3, when steps A1 and A2 each reduced m by only 1?

Hint

What happens to a parallel copy of the edge you contract?

Model answer

Contracting a pair with multiplicity μ removes all μ copies: one is contracted, and the other μ − 1 become self-loops, which are removed. Here μ = 2, so m drops by 2. In general mafter = mbefore − μ. Parallel edges created by a common neighbour do not change m; they only relabel endpoints.

Step A4: contract a–⁠d (parallel edges created)

  • Before: n = 4, m = 4. P(choose a–⁠d) = 1/4.
  • Neighbours of a: {b, g, h}, {c, f}, d. Neighbours of d: a, {c, f}. Common neighbour {c, f}, so a–⁠{c, f} and d–⁠{c, f} become {a, d}–⁠{c, f} × 2.
  • After: n = 3, m = 3.

    {a, d}–⁠{b, g, h}, {a, d}–⁠{c, f} × 2

Step A5: contract {a, d}–⁠{c, f} (self-loop removed)

  • Before: n = 3, m = 3. P(choose a copy of {a, d}–⁠{c, f}) = 2/3.
  • One copy is contracted and the other becomes a self-loop, which is removed.
  • After: n = 2, m = 1.

    {a, c, d, f}–⁠{b, g, h}

Result. The algorithm stops at 2 vertices and returns the cut {a, c, d, f} | {b, g, h} with one crossing edge (the original a–⁠b). This is the minimum cut, so the run succeeds.

Where the three cases occur in trace A: ordinary in A1; parallel edges created in A2 and A4; self-loops removed in A3 and A5.

The probability of following exactly this sequence of choices is 1/8 · 1/7 · 1/3 · 1/4 · 2/3 = 1/1008. This is not the success probability. Many other sequences also succeed (§5).

4. Worked trace B: a run that fails

Step B1: contract g–⁠h (parallel edges created)

  • Before: n = 7, m = 8. P = 1/8.
  • Common neighbour of g and h: b. So b–⁠g and b–⁠h become b–⁠{g, h} × 2.
  • After: n = 6, m = 7.

    a–⁠b, a–⁠c, a–⁠d, b–⁠{g, h} × 2, c–⁠f, d–⁠f

Step B2: contract a–⁠b (ordinary). This is the minimum-cut edge

  • Before: n = 6, m = 7. P(choose a–⁠b) = 1/7.
  • Neighbours of a: b, c, d. Neighbours of b: a, {g, h}. No common neighbour, one copy. This is the ordinary case. (The edges b–⁠{g, h} × 2 were already parallel. They are carried over as {a, b}–⁠{g, h} × 2, not newly created.)
  • After: n = 5, m = 6.

    {a, b}–⁠c, {a, b}–⁠d, {a, b}–⁠{g, h} × 2, c–⁠f, d–⁠f

  • The run is now doomed. Vertices a and b are inside the same composite vertex, and composite vertices only ever grow. So a and b end up on the same side of the final cut, and the final cut can never be {a, c, d, f} | {b, g, h}.

Checkpoint 4: when is a run lost?

After step B2, is there any way to finish the run (any choice of the remaining 3 contractions) that returns the minimum cut? Which kind of cut must be returned instead?

Hint

Where can a and b end up in the final 2-vertex graph?

Model answer

No. Every remaining sequence returns a cut with a and b on the same side, so it never returns the unique minimum cut. The run failed at step B2, the moment the cut edge was contracted. Nothing after that matters for success. Conversely, a run that never contracts a–⁠b must end with {a, c, d, f} and {b, g, h} as its two vertices, because contractions inside one side never merge the two sides, and the algorithm stops at 2 vertices. So:

run succeeds ⇔ no minimum-cut edge is ever contracted.

Step B3: contract c–⁠f (ordinary)

  • Before: n = 5, m = 6. P = 1/6.
  • Neighbours of c: {a, b}, f. Neighbours of f: c, d. No common neighbour, one copy, so this is ordinary.
  • After: n = 4, m = 5.

    {a, b}–⁠{c, f}, {a, b}–⁠d, {a, b}–⁠{g, h} × 2, {c, f}–⁠d

Step B4: contract {c, f}–⁠d (parallel edges created)

  • Before: n = 4, m = 5. P = 1/5.
  • Common neighbour {a, b}, so {a, b}–⁠{c, f} and {a, b}–⁠d become {a, b}–⁠{c, d, f} × 2.
  • After: n = 3, m = 4.

    {a, b}–⁠{c, d, f} × 2, {a, b}–⁠{g, h} × 2

Step B5: contract {a, b}–⁠{g, h} (self-loop removed)

  • Before: n = 3, m = 4. P(choose a copy) = 2/4 = 1/2.
  • One copy is contracted and the other becomes a self-loop, which is removed.
  • After: n = 2, m = 2.

    {a, b, g, h}–⁠{c, d, f} × 2

Result. The algorithm returns {c, d, f} | {a, b, g, h}. Its crossing edges in the original graph are a–⁠c and a–⁠d, so its value is 2, the number of parallel copies left at the end. This is a valid cut, but not a minimum one (k = 1), so the run fails. That is the Monte Carlo behaviour: the running time is fixed, and the answer can be wrong.

(Had step B5 contracted a copy of {a, b}–⁠{c, d, f} instead, the result would have been {g, h} | {a, b, c, d, f}, also of value 2. Either way the run fails.)

Where the three cases occur in trace B: ordinary in B2 and B3; parallel edges created in B1 and B4; self-loops removed in B5.

The probability of this exact sequence is 1/8 · 1/7 · 1/6 · 1/5 · 1/2 = 1/3360.

Common misconceptions while tracing

  • Merging parallel edges into one. This changes every later probability, and it can make a failed run look successful. In trace B, merging would leave a single edge {a, b, g, h}–⁠{c, d, f} at the end, and you would wrongly report a cut of value 1. The true value is 2. In trace A, step A3 would be computed as 1/5 instead of the correct 2/6.
  • Keeping self-loops. In trace A after step A3, a kept loop on {b, g, h} would give m = 5 and P(a–⁠d) = 1/5 instead of 1/4. A self-loop is not a choosable edge, because contracting it would not reduce n.
  • Using the original graph's probabilities. The probability is μ/m for the current m. It is not 1/8 at every step.
  • Choosing uniformly among vertex pairs instead of edges. In step A5 there are two adjacent pairs, but P({a, d}–⁠{c, f}) = 2/3, not 1/2, because it has two copies.
  • Confusing contracted edges with cut edges. The edges you contract end up inside the two sides. The cut is formed by the edges left over at the end. In trace A we contracted 5 edges (and removed 2 self-loops), and the cut is the 1 remaining edge.
  • "The run failed at the last step." In trace B the failure happened at step B2. Steps B3 to B5 only decided which wrong cut came out.

5. Probability analysis

5.1 Step-by-step along trace A

Let ni and mi be the number of vertices and edges just before step i. As long as no cut edge has been contracted, all k minimum-cut edges are still present (here, the single edge a–⁠b under its current name). So

P(step i avoids the min cut | steps 1..i − 1 avoided it) = 1 − k/mi.

Checkpoint 5: compare with the general bound

Fill in the column 1 − k/mi for trace A, and compare it with 1 − 2/ni. Why is every entry at least 1 − 2/ni?

Hint

In any multigraph reached without contracting a minimum-cut edge, the degree of a composite vertex X is the value of the cut {X, V \ X} in G. How small can that be?

Why ≥ 1 − 2/ni (the known result from the proof section). Every vertex X of the current multigraph has degree equal to the value of a cut of G, so deg X ≥ k. Summing over ni vertices gives mi ≥ kni/2, hence 1 − k/mi ≥ 1 − 2/ni. Multiplying over ni = n, n − 1, …, 3 gives the telescoping bound 2 / (n(n − 1)).

Why this graph does better. Every cut of G other than the minimum one has value ≥ 2 = 2k. Before the last step, at most one vertex can have degree 1 (the composite vertex {b, g, h} or {a, c, d, f}, once a whole side has merged). Every other vertex has degree ≥ 2. So 2mi ≥ 2(ni − 1) + 1, i.e. mi ≥ ni, and P(avoid) ≥ 1 − 1/ni. This bound is attained in A4 and A5.

Note that the product 5/16 is the probability of avoiding a–⁠b along the multigraphs of trace A. Different runs pass through different multigraphs with different mi, so the true success probability averages over all of them (next subsection).

5.2 The exact single-run success probability

Method 1 (computer, exhaustive). karger_verify.py computes it in two independent ways:

  • Exhaustive enumeration of every possible sequence of edge-copy choices (5040 sequences, each weighted by its probability ∏ 1/mi).
  • Dynamic programming over the 119 reachable partitions of V. From each partition, every pair X–⁠Y with multiplicity μ is taken with probability μ/m.

Both give

P(one run returns the minimum cut) = 9/28 ≈ 0.3214

Method 2 (by hand, optional). There is an equivalent way to run Karger's algorithm: shuffle the 8 original edges into a uniformly random order, then go through the list. Contract each edge unless it has already become a self-loop (then skip it), and stop at 2 vertices. This is the same process because at every moment the edges not yet looked at are in uniformly random order. So the next one that is not a self-loop is uniformly distributed over the non-loop unseen edges, and those are exactly the edges of the current multigraph.

In this view, the run succeeds exactly when, by the time a–⁠b comes up in the list, both sides are already single vertices (so the algorithm has stopped). The 4-cycle side is connected by any 3 of its 4 edges, and the triangle side by any 2 of its 3 edges. Let j be the number of edges before a–⁠b in the shuffled list. Then j is uniform on {0, …, 7}, and the j edges before it are a uniformly random j-subset of the other 7:

  • j ≤ 4: impossible (we need 3 + 2 = 5 edges).
  • j = 5: we need exactly 3 cycle edges and 2 triangle edges: C(4, 3) · C(3, 2) / C(7, 5) = 12/21 = 4/7.
  • j = 6 or 7: always fine.

P = 1/8 · (4/7 + 1 + 1) = 18/56 = 9/28. ✓

Where the failures go. The exact output distribution (from the DP) is:

returned cutvalueprobability
{b, g, h} | {a, c, d, f} (minimum)19/28 ≈ 0.321
{g}, {h}, {g, h} vs the rest21/12 each, so 1/4 in total
{c}, {d}, {f}, {c, f}, {d, f}, {c, d, f} vs the rest21/14 each, so 3/7 in total

Every failed run returns a cut of value 2, never more.

Monte Carlo check. 100,000 simulated runs (seed 3821) succeeded with frequency 0.32116. The standard error is √(p(1 − p)/N) ≈ 0.0015, so this is 0.18 standard errors from 9/28. It agrees.

5.3 Comparison with 2 / (n(n − 1))

2 / (n(n − 1)) = 2/42 = 1/21 ≈ 0.048 ≤ 2/7 ≈ 0.286 ≤ 9/28 ≈ 0.321.

The exact value is about 6.75× the general bound. The bound is a worst case over all graphs. Its proof assumes every vertex might have degree exactly k at every step, i.e. mi as small as kni/2. (That worst case really happens: on a cycle Cn, every vertex has degree k = 2 and each particular minimum cut is found with probability exactly 2 / (n(n − 1)).) In G:

  1. every non-minimum cut has value ≥ 2k, so almost every vertex has degree ≥ 2k and mi ≥ ni, twice the worst case. This alone raises the guarantee to 2/7;
  2. many reachable multigraphs have even more edges than ni (e.g. m = 8 > 7 at the start), so the true value 9/28 is higher still.

Common misconceptions in the probability analysis

  • "5/16 (the product along trace A) is the success probability." It is only for one particular path of multigraphs. The answer must average over all runs: 9/28.
  • "1/1008 is the success probability." That is the probability of one exact sequence of choices.
  • "2 / (n(n − 1)) is the success probability." It is a lower bound valid for every graph. A specific graph can (and usually does) do much better.
  • "P(avoid at step i) = 1 − k/m with the original m." It must use the current mi, which shrinks, so later steps are riskier.

5.4 Looking ahead

A single run succeeds only with probability 9/28. Since runs are independent, repeating the algorithm and keeping the smallest cut found drives the failure probability down quickly. How many repetitions are needed in general is the topic of Problem 2.

If exactly j K4-edges come first, the probability of that is (7 − j)/28, and the j edges connect K4 with probability 16/20 for j = 3 and 1 for j ≥ 4 (K4 is 3-edge-connected). So P = 4/28 · 16/20 + (3 + 2 + 1)/28 = 23/70.

Problem 2: Amplifying Karger's Success Probability

Read this after Problem 1. Its §5.4 asks how many times we must rerun the contraction algorithm to make the final answer reliable.

What you will be able to do after this problem

  1. Trace which cut is kept across several complete runs and prove when that rule succeeds.
  2. Derive the probability of failure after independent runs and explain what happens when the same randomness is reused.
  3. Find the least number of runs for a given failure target when the single-run success probability is known.
  4. Give a sufficient number of runs when only the number of vertices is known.

Notation. A run starts from the original graph and contracts edges until two blocks of original vertices remain. The cut size is the number of original edges crossing between the blocks, counting parallel copies separately. For a connected, undirected, unweighted graph J with n ≥ 2 vertices, write k for the global minimum cut size and p for the probability that one run returns a cut of size k. Let T ≥ 1 be an integer number of runs and 0 < δ < 1 the largest acceptable probability of final failure.

1. The problem

Use the same graph G as in Problem 1. Call the cuts returned by Trace A and Trace B A and B, respectively. Cut A is the unique minimum cut, with size 1 and crossing edge a–⁠b. Cut B has size 2. The exact probability that one full run on G returns a minimum cut is pG = 9/28 (Problem 1, §§2–4 and §5.2).

In the first problem, each contraction changed the graph for the next step. Here, each completed run gives us one candidate cut, and a new run starts again on the original graph.

Questions.

  1. (Choosing the output) Suppose three complete runs on G return B, A, B in that order. Using the returned cuts and their sizes, give a rule for which cut to keep after each run. Apply it to this sequence. Then prove for any input J that the rule returns a global minimum cut if and only if some run does.
  2. (Independent runs and a replay) Use the shuffled-edge description from Problem 1's §5.2. Compare two runs on G with independently shuffled edge orders to two runs that use the same randomly shuffled order. In each case, identify the event that makes the final cut fail and give its probability. Extend the independent case to T runs on J.
  3. (Exact run count) Use the known pG and the exact failure probability from Question 2 to find the least positive integer T that gives failure probability at most δ on G. Prove minimality and state the corresponding rule for a graph with known p.
  4. (A guarantee from n) Suppose p is unknown. You know that on an n-vertex graph, one run returns any fixed minimum cut with probability at least p0 = 2 / (n(n − 1)). Use this bound to give a sufficient integer T in terms of n and δ. Explain why it gives a guarantee even when the exact run count is unknown.

2. Worked selection: keep the smallest cut seen

Keep the first cut. After each later run, retain the smaller of its cut and the cut already kept. Either cut can be kept in a tie. The repeated contraction algorithm restarts from the original graph with independent randomness on each run. See Karger and Stein, §4, opening paragraph and Yu, §2.

Checkpoint 1: what if two cuts tie?

Suppose two runs return different partitions with the same cut size. Can choosing one over the other change whether the selected cut is a global minimum cut?

Hint

What property of a cut determines whether it is minimum?

Model answer

Two valid cuts with the same size have the same status. If their size is k, both are global minimum cuts. If their size exceeds k, neither is.

Why the rule works. The two blocks left by a run partition the original vertices. The edges still crossing between those blocks are exactly the original edges crossing that partition. Thus each run returns a valid cut of the original graph. This correspondence is described in Karger and Stein, §2, pp. 609–610.

Let Xi be the size returned by run i. Each Xi ≥ k, and the size kept after T runs is kT = min1≤i≤T Xi. If any run returns size k, then kT = k. Conversely, the minimum of a finite list is attained by an entry, so kT = k implies that some Xi = k. Therefore

{kT = k} = ⋃i=1..T {Xi = k}.

The rule compares cut sizes to one another. The true size k serves as the benchmark in the proof.

3. Worked comparison: fresh randomness and a replay

Write Fi = {Xi > k} for failure of run i. By §2, the retained cut after two runs fails exactly when both runs fail. On G, each individual run has failure probability qG = 1 − pG in either setup in Question 2.

Checkpoint 2: what changes when we replay an edge order?

In both setups the first run fails with probability qG. Given that it fails, what is the probability that the second run fails in each setup?

Hint

For a fixed input, a fixed edge order determines the sequence of contractions and the final cut.

Model answer

With independent orders, the second run still fails with probability qG after observing the first failure. With a replay, the second run returns the first run's cut, so it fails with conditional probability 1.

The two-run failure probability is P(F1 ∩ F2) = P(F1)P(F2 | F1). The two setups give different values for the second factor.

How the two runs on G are madeEvent of final failureProbability

The replay comparison uses the random edge-order interpretation in Karger, §2 and Problem 1's §5.2.

Extend to T independent runs. On the same input J, each run has failure probability 1 − p. The failure event of a run is determined by its own random choices. Independent random choices across runs therefore make F1, …, FT mutually independent. Taking the complement of the success event in §2 gives

P(kT > k) = P(⋂i=1..T Fi) = ∏i=1..T P(Fi) = (1 − p)T.

Hence the exact success probability is 1 − (1 − p)T. For G it is 1 − (1 − 9/28)T. When 0 < p < 1, each additional independent run multiplies the remaining failure probability by 1 − p, which is strictly between zero and one. This is the amplification step in Canonne, Algorithm 11 and its analysis, p. 63.

4. Worked derivation: find the least number of runs on G

To achieve failure probability at most δ on G, the exact condition from §3 is qGT ≤ δ.

Checkpoint 3: which way does the inequality go?

Taking logarithms gives T ln qG ≤ ln δ. What is the sign of ln qG? After dividing, is the condition a lower or an upper bound on T?

Hint

Compare qG to 1 and use ln 1 = 0.

Model answer

Since 0 < qG < 1, ln qG < 0. Dividing by it reverses the inequality, so T must be at least ln δ / ln qG.

The logarithm is strictly increasing and the last division is reversible. Thus the target holds exactly when T ≥ ln(1/δ) / [−ln qG]. This bound is positive, so the least positive integer satisfying it is

Tmin(G, δ) = ⌈ln(1/δ) / [−ln(1 − 9/28)]⌉.

Every smaller positive integer lies below the real threshold and has failure probability greater than δ. The same argument on a graph with known 0 < p < 1 gives

Tmin(p, δ) = ⌈ln(1/δ) / [−ln(1 − p)]⌉.

When p = 1, one run suffices. These least-count formulas follow by solving the exact failure condition from Canonne's analysis of Algorithm 11.

5. Worked derivation: guarantee success from the graph size

The one-run probability of returning a particular minimum cut is at least p0 = 1/C(n, 2) = 2 / (n(n − 1)). This is the bound in Problem 1's §5.3. See Karger and Stein, Theorem 2.2 and Yu, Theorem 3.

Checkpoint 4: a fixed minimum cut and any minimum cut

Fix one minimum cut C*. Which event contains the other: returning C*, or returning a global minimum cut? What does that tell us about p?

Hint

A graph may have several distinct cuts of size k.

Model answer

Returning C* is one way to return a global minimum cut. The first event is contained in the second, so p ≥ P(C* is returned) ≥ p0.

Apply p ≥ p0 to the exact failure identity from §3. The exponential function lies above its tangent at zero, so 1 − x ≤ e−x. Together with 0 ≤ 1 − p ≤ 1 − p0, this gives

P(kT > k) = (1 − p)T ≤ (1 − p0)T ≤ e−p0T.

This is the same chain of bounds used in Canonne, p. 63. Requiring e−p0T ≤ δ gives p0 T ≥ ln(1/δ). Consequently a sufficient count is

Texp(n, δ) = ⌈C(n, 2) · ln(1/δ)⌉.

For n ≥ 3 we may also solve (1 − p0)T ≤ δ directly, using the logarithm step in §4. This gives another sufficient count

Tpow(n, δ) = ⌈ln(1/δ) / [−ln(1 − p0)]⌉.

For n = 2 the bound forces p = 1, and one run suffices. For larger graphs both counts certify the target using only n and δ. The graph's actual least count depends on p. For example, with δ = n−c for a fixed c > 0, the exponential certificate uses O(n2 ln n) runs, the regime in Karger, Corollary 2.1.

Appendix: answers to the unguided follow-up

Show proof

From pH ≥ p0, we get 1 − pH ≤ 1 − p0, hence −ln(1 − pH) ≥ −ln(1 − p0). Also, 1 − p0 ≤ e−p0 gives −ln(1 − p0) ≥ p0. The three denominators are positive, so dividing the same positive numerator ln(1/δ) by them reverses their order. The ceiling function preserves the resulting inequalities. Thus

Tmin(pH, δ) ≤ Tpow(nH, δ) ≤ Texp(nH, δ).

The two sufficient counts depend only on nH and δ. The least count formula uses pH. That least count meets the target by the exact identity in §3, and the other counts meet it by the bounds in §5.
